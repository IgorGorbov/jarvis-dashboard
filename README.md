# Jarvis Dashboard

Панель наблюдения за прогонами агента Jarvis: что он делает сейчас, чем кончились
прошлые запуски, кнопки запустить / ответить / отменить. Читает артефакты с диска,
в репозиторий агентов ничего не приносит.

Зависимостей нет, сборки нет. Нужен Node 24.

```
yarn start        # http://localhost:4100
yarn dev          # с перезапуском по изменению файла
yarn test         # разборщики, синтаксис страницы, сверка со схемами агента
yarn coverage     # какие сценарии конвейера ещё не видели живьём
```

## Настройки

`.env` рядом с панелью, всё необязательно. Образец — `.env.example`.

| Переменная | Что задаёт | По умолчанию |
|---|---|---|
| `JARVIS_ARTIFACTS` | каталог артефактов | `../agents/artifacts/jarvis` рядом |
| `JARVIS_A2A` | адрес агента для кнопок | `http://localhost:4000` |
| `PORT` | порт панели | `4100` |
| `JARVIS_SCHEMAS` | `schemas.ts` агента, только для двух проверок | рядом |

Путь можно передать первым аргументом, он главнее `.env`.

## Полоса шагов

`analyze → prepare → [implement → check → review] → pr`. Три средних крутятся в
петле, поэтому «завершился» для них не значит «пройден».

| Вид | Значение |
|---|---|
| `analyze ✓` | пройден окончательно; только у шагов вне петли |
| `review ◉` | идёт сейчас: стартов больше, чем завершений |
| `check ×3` | шаг петли выполнялся три раза |
| `analyze ⏸` | ждёт человека: вопросы, подтверждение или отмена |
| `check ✕` | здесь прогон остановлен |

Справа — текущий вызов инструмента, а если трасса молчит дольше двух минут,
«тишина N мин». У каждого блока есть подсказка, легенду держать в голове не надо.

Цвет полоски прогона в списке — это исход: зелёный `pr`; красный `kept`,
`stopped`, `failed`; жёлтый `asked`, `cancelled`, `awaiting-confirmation`,
`no-changes`; серый — исход неизвестен, прогон идёт или оборвался без записи.

## Что стоит знать

**Аутентификации нет.** Кто открыл порт, тот управляет агентом. На `localhost`
это безопасно, наружу — только через SSH-туннель или прокси с авторизацией.

**Панель читает диск, а не сеть.** Каталог артефактов должен быть доступен
локально: либо она стоит на машине агента, либо каталог смонтирован.

**Запуск двухшаговый.** Первый прогон разбирает задачу и останавливается на
пересказе, сохранив разбор; второй — тот же текст с галочкой — идёт в реализацию.
Галочка на первом запуске даёт отказ: сохранять ещё нечего.

**Ответа на запуск ждать нельзя** — агент синхронно дожидается всего прогона.
Панель ждёт три секунды, за них приезжает только отказ, дальше смотрит в журнал.

## Данные

| Что | Откуда |
|---|---|
| лента событий | `events.jsonl` в корне, дочитывание хвоста по офсету |
| занят, срок, ждущие ответа | `state.json` в корне |
| всё про прогон | `run.jsonl` в папке прогона |
| ходы и вызовы инструментов | `trace.jsonl` там же |
| диф | `diff.aborted.patch` либо `diff.final.patch` |

Накапливается мало: папка прогона около двух килобайт. Трогать нельзя `pending/`
— там разбор, ждущий подтверждения.

## Проверки

`yarn test` — четыре шага без зависимостей: разборщики (проверены порчей, восемь
поломок из восьми ловятся), компиляция скрипта страницы, сверка решений и видов
исхода со `schemas.ts`, счётчик покрытия сценариев. Две последние пропускаются,
если схем агента рядом нет.

`yarn coverage` печатает решения, которых не было ни на одном прогоне, и рядом —
задачу, готовую к вставке в поле запуска. Задачи берутся из `scenarios.json`;
файл локальный, в git его нет, без него покрытие считается, но подсказать нечем.
